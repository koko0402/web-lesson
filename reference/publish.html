公開する

自分のパソコンの中にあるだけのサイトを、URLを送れば誰でも開ける状態にする。
どちらも無料。早いほうは15分で終わる。

どこに出すか 2つの違い 出す前の確認 A. GitHub Pages B. Firebase Hosting 公開したあと うまくいかないとき
このページに出てくる管理画面の絵は、実際の画面に合わせて描いたもの。 本物はログインしないと見られないので、写真にするとアカウント名やメールアドレスが写ってしまう。 ボタンの名前と場所は本物と同じにしてあるので、そのとおりに押せば進める。

2つの違い

見に来た人から見ると違いはほぼ無い。どちらも https で同じように出るし、速さも変わらない。 違うのは作る側の都合だけ。

実際に困るのは、この2つだけ

① URL に「リポジトリ名」がはさまる（GitHub Pages） だから 先頭に / を付けたパスを書くと、公開した瞬間に全部消える。

✕ 壊れる

background: url(/images/sora.jpg);

ユーザー名.github.io/images/… を見に行ってしまう

○ 大丈夫

background: url(images/sora.jpg);

先頭の / を消すだけ。 この講座の書き方なら最初からこう

自分のパソコンでは動いていたのに、公開したら画像だけ全部出ない—— という時は、まずこれを疑う。Firebase 側ではこれは起きない。
② コードが全部読まれる（GitHub Pages） 書きかけも、コメントも、直した履歴も全部見える。 練習のうちはむしろ利点（人に見せられるし、他の人のも読める）。
なお JavaScript の中身はどちらでも読まれる。 ブラウザに配っている以上あたりまえで、そこに差は無い。 違うのは「作業の履歴まで見えるか」だけ。
迷ったら GitHub Pages コマンドを1つも打たなくていいのが、最初のうちはいちばん大きい。 「みんなで共有する機能」が要ると決まってから Firebase にまとめて移ればいい。 同じファイルをそのまま置けるので、移るのは簡単。

出す前の確認（3つだけ）

  1. 個人情報が書かれていないか
    本名・住所・学校名・電話番号・通っている場所。一度出すと、消しても誰かの手元に残る。 コメントアウトの中も見る（<!-- --> の中身も全部見えている）
  2. 画像は自分のものか
    拾ってきた画像・推しの写真は外す。 くわしくは 写真のページ の⑥
  3. ファイル名が半角の英数字か
    写真1.JPG のような名前は、公開先で出ないことがある。 photo1.webp のようにしておく
パスワードや鍵を書いていないか JavaScript に書いたものは全部、見に来た人から読める。 「JSの中だから見えない」ということは一切ない。 F12 を押せば誰でも中身が見える、と思っておくこと。
A

GitHub Pages で公開する

ブラウザだけで終わる。コマンドは1つも打たない。

1. アカウントを作る

  1. github.com を開いて Sign up
  2. メールアドレス・パスワード・ユーザー名を決める
    ユーザー名はURLの一部になる（https://ユーザー名.github.io/…）。 本名は避けて、英数字で短いものにする
  3. 届いたメールのコードを入れて完了

2. 置き場（リポジトリ）を作る

右上の ＋ → New repository。

① 名前を半角英数字で（例 my-site）。スペースや日本語は使わない ② Public のまま（Private だと無料では公開できない） ③ Create repository を押す

3. ファイルを置く

できた画面の uploading an existing file（または Add file → Upload files）を押す。

① 作ったフォルダの中身を、まるごとここへドラッグ。 フォルダごとではなく、中身（index.html が一番上に来るように） ② Commit changes を押すと保存される
「フォルダごと」だとうまくいかない my-site フォルダごと入れると、URLが …/my-site/my-site/ になって トップページが表示されない。 フォルダを開いて、中の index.html・style.css・img フォルダを選んで入れる。

4. 公開を on にする

上の Settings → 左のメニューの Pages。

① 左メニューの Pages ② Branch を main に ③ Save

5. 待つ

1〜2分で、この緑の帯にURLが出る。これが自分のサイトのURL。
できたら … そのURLをスマホで開いてみる。 同じものが出れば公開できている。

直したあとは

同じリポジトリで Add file → Upload files に、直したファイルを入れ直して Commit changes。1〜2分で反映される。同じ名前のファイルは上書きされる。

B

Firebase Hosting で公開する

あとで みんなで共有するデータ（感想・スコア・ログイン）を足すつもりなら、 最初からこちらにしておくと、同じプロジェクトの中でまとまる。
使い方そのものは Firebase のページ にまとめた。

1. プロジェクトを作る

console.firebase.google.com を開いて、Googleアカウントでログイン → プロジェクトを追加。

① 名前を入れる（英数字）。下に出るプロジェクトIDがURLになる ② アナリティクスはオフのまま 続行

2. パソコンに道具を入れて、公開する

先に nodejs.org から Node.js（LTS）を入れておく。 そのあと、VSCode の 表示 → ターミナル を開いて、上から順に打つ。

打つのは 太字の4行だけ。? で始まる行は質問なので、 矢印キーで選んで Enter。最後の Overwrite? は必ず No （Yes にすると自分の index.html が消される）。
できたら … 最後に出る https://〇〇.web.app が自分のサイトのURL。

直したあとは

ターミナルで firebase deploy を打つだけ。数十秒で反映される（GitHub Pages より速い）。

無料の範囲 Firebase の無料プラン（Spark）は、個人サイトならまず超えない。 超えそうになると Google からメールが来るし、 クレジットカードを登録していなければ勝手に課金されることはない（止まるだけ）。

公開したあと

やることやり方
スマホで開く いちばん大事。URLを自分に送って、実機で見る。 パソコンで大丈夫でも、スマホで崩れていることがよくある
横スクロールが出ていないか 指で左右に動いてしまうなら、どこかがはみ出している。 便利CSS の「スマホ対応」を見る
読み込みの速さ 開くのに3秒以上かかるなら、たいてい写真が重い。 写真のページで軽くする
人に送る URLをそのまま送るだけ。相手に何かを入れてもらう必要はない

うまくいかないとき

症状たいていの原因
404 と出る index.html が一番上の階層にない。 フォルダごと入れてしまっていないか確認する。 名前も Index.html ではなく全部小文字で
真っ白 まだ公開処理の途中。2〜3分待って再読み込み。 それでも白ければ F12 の Console を見る
画像だけ出ない 大文字小文字の違い。自分のパソコンでは Photo.jpg と photo.jpg が同じ扱いだが、 公開先は別のファイルとして扱う。ここで一番よく詰まる
CSSが効いていない 同じく大文字小文字か、css/style.css のようなフォルダの位置のずれ
直したのに変わらない ブラウザが古いほうを覚えている。Ctrl + Shift + R で強制的に読み直す。 スマホなら、いったんタブを閉じて開き直す
日本語が文字化けする <meta charset="UTF-8"> が <head> のいちばん上にあるか
消したくなったら GitHub は Settings → 一番下 → Delete this repository。 Firebase は Hosting の画面から サイトを削除。 どちらもすぐ消せるので、まず出してみていい。
