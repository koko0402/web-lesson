問 4Emmet を使ってみるやさしい

HTMLファイルで次の省略形を打って Tab を押すと、何が出るか予想してから試して。

打つもの出てくるもの（予想）
ul>li*6
table>(tr>th*2)+(tr>td*2)*3
.card*3
h2{すきなもの}
答え

ul>li*6 … ul の中に li が6個
table>(tr>th*2)+(tr>td*2)*3 … 見出し2マスの行が1つ＋データ2マスの行が3つ
.card*3 … <div class="card"> が3個
h2{すきなもの} … <h2>すきなもの</h2>

>＝中に入れる、*＝繰り返す、+＝並べる、 { }＝中身の文字、.＝class。これだけ覚えると入力量が半分になる。

デバッグ 4足し算が変ふつう

2つの入力欄に 5 と 3 を入れて計算させたら、8 ではなく 53 と出た。なぜ？

答え

入力欄から取った .value は、数字に見えても文字列。 文字列どうしの + は「連結」になるので "5" + "3" は "53" になる。

DAY 6 ／ JavaScript②

問 15じゃんけんアプリふつう

グー・チョキ・パーのボタンを押すと、相手の手がランダムに決まり、 勝ち・負け・あいこが表示されるページを作って。

ヒント

グー＝0、チョキ＝1、パー＝2 と数字にする。
自分を a、相手を i としたとき、自分が勝つのは次の3通り。
（a=0, i=1）／（a=1, i=2）／（a=2, i=0）
ここに規則性が見つかると、条件を1行で書ける。

答えの一例

(a + 1) % 3 === i が肝。0→1、1→2、2→0 と輪っかになるので、 あまり（%）を使うと3通りの条件が1行にまとまる。

もちろん if を3つ並べて書いても正解。 動くほうが先、短くするのはあと。

デバッグ 5何も選んでいないのに勝敗が出るむずかしい

問15を「数字を入力してボタンを押す」形で作ったところ、 入力欄が空のままボタンを押しても勝ち負けが出てしまう。直して。

ヒント

空の入力欄の .value は ""（空の文字列）。 それを Number() に通すと何になるだろう？ F12 の Console で Number("") と打って確かめてみて。

答え

Number("") は 0 になる。つまり「何も入力していない」が 「グー（0）を出した」と同じ扱いになってしまうのが原因。

数字に変換する前に、空かどうかを調べる。

これが「入力チェック」。 自分で使っているうちは気づかないが、他人に触らせると3秒で見つかる。 「変な入力をされたらどうなるか」を考えるクセをつけて。

問 19手札を1枚だけ引き直せるようにするふつう

「この1枚が使えない」というときに、1回だけ交換できるボタンを足して。

ヒント

game に「もう引き直したか」を覚えるフラグを1つ持たせる。 手札の配列の中身を、新しいことばで上書きすればいい。

答えの方針
  1. game に redraw: true を足す（配るたびに true に戻す）
  2. カードを長押し／右のボタンで「この1枚を引き直す」を出す
  3. game.hand[i] = allWords()[rnd(allWords().length)]; で入れ替える
  4. 入れ替えたら game.redraw = false; にして、2回目を止める

DAY 7 の型どおり、先に「何が起きるか」を書き出してから手を動かして。 いきなり書き始めると、すでに穴に入れたことばを引き直して表示が食い違う。
