よくある勘違い

エラーは出ないけれど、思い込みのせいで遠回りする話をまとめた。
エラー辞典 が「症状」から引くものなら、こちらは「思い違い」から引くものだ。

言語について作り方について 見え方について公開と権利AIについて

言語について

JavaScript は Java の一種

まったく別の言語

名前が似ているだけで、作った会社も文法も用途も違う。 当時 Java が流行っていたので、名前を借りて注目を集めようとしただけ。 「Java」で検索すると欲しい答えが出てこないので、必ず「JavaScript」で調べて。

HTML はプログラミング言語

マークアップ言語

計算も分岐もできない。「ここは見出し」「ここは画像」と印をつけるだけの言語。 だから HTML を覚えても「プログラムが書けるようになった」ことにはならないし、 逆にHTMLが書けなくてもプログラマーではあるという人もいる。

この講座で「プログラム」と呼べるのは DAY 5 以降の JavaScript だけ。

CSSが書ければ何でもレイアウトできる

できるが、順番がある

HTMLの構造がめちゃくちゃだと、CSSでいくら頑張っても整わない。 「CSSで直せない」と思ったときは、たいていHTMLの組み方が原因。 先にHTMLを直すほうが早い、というのはよくある。

Python を覚えないとWebは作れない

この講座の範囲では1行も要らない

ブラウザが読めるのは HTML・CSS・JavaScript だけ。 Python が必要になるのは「サーバー側の処理を自分で書きたくなったとき」で、 しかも Firebase のようなサービスを使えば、それすら書かずに済む。

作り方について

全部おぼえてから作り始める

おぼえる前に作り始めて

タグもプロパティも数百ある。全部おぼえてから始めようとすると、永遠に始まらない。 必要になったときに調べる、で十分。プロも毎日調べている。

おぼえるべきは「調べ方」と「直し方」の2つだけ。

コードを全部書いてから、まとめて確認する

1つ書くごとに確認して

まとめて書くと、動かなくなったときにどこが原因か分からなくなる。 書く → Ctrl+S → F5、を1分に1回。 遠回りに見えて、これが一番速い。

まず見た目から作る

データと構造が先

先に見た目を作り込むと、あとでデータの持ち方を変えたくなったときに全部やり直しになる。 データを決める → 表示する → 操作を付ける → 最後に飾る、の順が結局いちばん速い。

エラーが出ない＝正しく動いている

別の話

エラーは「文法として成立しない」ときに出るもの。 文法が合っていて意図と違うことをしている場合、何も言われない。 「思ったとおりに動かないがエラーも出ない」ときは、console.log で 中身を見ていくしかない。

動いているコードは触らないほうがいい

壊して覚えるのが一番速い

コピーを取っておけば、いくら壊しても戻せる。 innerHTML = "" を消したらどうなるか、flex: 1 を外したらどうなるか。 やってみたほうが、説明を読むより10倍わかる。

見え方について

自分の画面で見えているものが、みんなにも同じに見える

かなり違う

画面の大きさ、ブラウザの種類、フォントの有無、文字サイズの設定。 条件が変われば見え方も変わる。スマホでは特に別物だと思って。 F12 のスマホ表示で必ず確認する癖をつけると、あとで慌てずに済む。

フォントを指定すれば、その書体で表示される

相手のPCに入っていなければ別の書体になる

font-family は「この書体があれば使って」というお願いにすぎない。 だからカンマ区切りで候補を並べ、最後に sans-serif のような 大分類を書いておくのが決まりになっている。

保存すればブラウザの表示も変わる

リロードが要る

保存は「ファイルを書き換える」だけ。ブラウザは読み込んだ時点の内容を表示し続ける。 F5 で読み直して。それでも変わらないときは Ctrl+Shift+R。

localStorage に保存すれば、どこからでも見られる

その端末のそのブラウザの中だけ

同じPCでも Chrome と Edge では別。スマホからは当然見えない。 「保存」というより「そのブラウザが覚えている」くらいの感覚が正しい。 みんなで共有したいなら Firebase などが必要になる。

公開と権利

サイトを公開するにはお金がかかる

この規模なら無料でできる

GitHub Pages などを使えば0円。独自のドメイン名（○○.com）が欲しくなったときに 初めてお金の話が出てくる。まずは無料の範囲で十分。

ネットで拾った画像は自由に使える

使えない

画像・イラスト・音楽には作った人の権利がある。 身内で見せるだけならまだしも、公開すると問題になり得る。 公開するなら、自分で作ったものか、使ってよいと明示されている素材に差し替えて。

この教材のキャラクター画像も、教材の中だけで使っている。

ローカルで動いたなら、公開しても同じに動く

大文字小文字で止まることがある

自分のPC（Windows）は Photo.png と photo.png を同じ扱いにするが、 公開先のサーバーは別物として扱う。 「ローカルでは出た画像が公開したら出ない」は、ほぼこれ。

公開したページは、あとから完全に消せる

消したつもりでも残ることがある

検索エンジンやアーカイブサービスが控えを持っている場合がある。 本名・住所・学校名・電話番号は最初から書かないのが唯一の対策。 公開する前に、必ず一度ファイル全体を見直して。

AIについて

AIが書いたコードは正しい

動くとは限らないし、古いこともある

それらしいコードが出てくるのと、正しく動くのは別。 読んで、動かして、確かめるのは結局こちらの仕事。 「動かない」と言えば直してくれるが、何が違うのか分からないままだと同じ所をぐるぐるする。

AIを使うのはズルい

プロも毎日使っている

面倒な部分を任せたり、下書きを出させたりするのは普通のこと。 問題なのは読まずに貼ることだけ。出てきたものから盗めるものを盗んでいれば、 使わない人より速く伸びる。

AIに丸投げすればサイトが完成する

「何を作るか」は代わりに決めてもらえない

作りたいものが決まっていなければ、頼むこともできない。 逆に、決まってさえいれば、コードの部分はかなり任せられる。 だから DAY 7 の「作り方の型」がいちばん長く使えるという話になる。

こういう勘違いは、恥ずかしいものではなくて ほぼ全員が一度は通るもの。むしろ早めに踏んでおいたほうが、あとが楽。
