今日の核心

やることは、いつもこの3つ

① 取ってくる

HTMLの中から、動かしたい部品を探して変数に入れる。

② 何かする

「クリックされたら」を予約して、その中で計算や判定をする。

③ 書き戻す

結果を画面に反映する。文字・見た目・クラスなど。

今日書くコードは、全部この形 長いプログラムに見えても、この3ステップの繰り返し。
止まったら「今どれをやろうとしてる？」と自分に聞くと、だいたい進む。
順番は必ずこの通り 取ってこないと動かせない。予約しないと実行されない。書き戻さないと見えない。

基本 ④

if ── 場合分け

C言語とほぼ同じ else if が2語に分かれている（C の else if と同じ）だけ。 丸かっこ・波かっこの使い方も同一。

上から順に判定される

最初に当てはまった1つだけが実行され、残りは無視される。 だから条件は厳しいものから書くのが鉄則。

× よくある間違い

count が 12 でも、先に >= 5 に当たってしまう。

最終課題で使う 「まだ作っていない人がいるか」「指輪が0になったか」で進む先が変わるのも、まさにこの if / else if / else 。

alert は知らせるだけ。 confirm は OK / キャンセルで true / false が返る。

JavaScript の文の形 window.alert("こんにちは"); は 「誰の」「何をする」「材料」という形をしている。
window（画面）の alert（知らせる）を、"こんにちは" という材料で実行せよ。 この もの . 動作( 材料 ) の形は、これから何度も出てくる。
alert は使いすぎない 押すまで操作が止まる。 テストのときは便利だが、完成品では画面に文字を出すほうが親切。
