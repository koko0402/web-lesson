登場人物は3人だけ

HTML・CSS・JavaScript

HTML ／ 骨組み

「ここは見出し」「ここは画像」と意味を決める。家でいう柱と部屋。
これが無いと何も始まらない。

CSS ／ 見た目

色・大きさ・並び方を決める。家でいう壁紙と家具の配置。
無くても動くが、ダサい。

JavaScript ／ 動き

押したら変わる、計算する、覚える。家でいう電気とスイッチ。
ここで初めて「プログラム」。

順番も、この通り。 骨組みが無いのに壁紙は貼れないし、電気配線もできない。だから HTML → CSS → JS の順で覚えるのが一番ラクなんだ。

よくある疑問 ①

「プログラミング＝Python」じゃないの？

よく聞く言語だけど、この講座では1行も使わない。理由はシンプルで——

ブラウザは Python を読めない 世界中のブラウザが理解できる言語は、今のところ JavaScript ただ一つ。 Python のファイルを置いても、ブラウザには「ただの文字」にしか見えない。
言語おもな居場所この講座
HTML / CSSブラウザの中（見た目）使う
JavaScriptブラウザの中（動き）使う
Pythonサーバー・AI・データ分析使わない
C / C++アプリ本体・組み込み・ゲーム使わない

じゃあ Python はいつ使う？

  • サイトの裏側（会員データを保存する等）を自作したくなったとき
  • AI・機械学習をやりたいとき
  • Excel処理やスクレイピングの自動化

ただし今回は、裏側は DAY 8 で紹介する Firebase（プログラムを書かずにデータ保存できる仕組み）に任せる。
だから Python を覚えなくても、動くサービスは作れる。

結論 「Webサイトを作る」という目的に対して、Python は遠回り。最短距離は HTML → CSS → JS 。

技術より、たぶんこっちが大事

作りたいものが先。技術はあと

コードが書けるようになっても、何を作るか決まっていないと1行も進まない。 この講座は毎回、次の順番で進める。

1. イメージ

どんなものを作りたいか。絵でも箇条書きでもいい。ここが9割。

2. 分解

欲しい機能を言葉にして、必要な部品を並べる。「このボタンを押したらこうなる」まで細かく。

3. 作って直す

動かす → 壊れる → 直す。この往復が上達そのもの。一発で完成させようとしない。

DAY 7 でこの型をフルで使う 「作りたい → 機能を出す → 問題点を潰す → 図にする → 実装 → 触って直す」。 くわしくは reference/workflow.html にまとめてある。
先に言っておく

AIは使っていい。ただし使い方がある

○ こう使う

  • エラー文をそのまま貼って「これ何？」と聞く
  • 「こういう機能を足したい。何が必要？」と相談する
  • 作った後に「もっと短く書ける？」とレビューさせる
  • 大まかな下書きを出させて、自分で読んで直す

× これは伸びない

  • 丸投げして、出てきたコードを読まずに貼る
  • 動かないとき、理由を見ずに何度も作り直させる
  • 何を作りたいか決まってないのに聞く

→ 結局直せないので、一歩も進めなくなる。

プロも使っている 下書きを出させたり、面倒な部分を任せるのは普通のこと。大事なのは 出てきたものを判断できる自分でいること。そのための9回。
